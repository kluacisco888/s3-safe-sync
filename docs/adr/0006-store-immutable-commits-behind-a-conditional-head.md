# Store immutable commits behind a conditional Head

Replicas will upload immutable content, read each new Blob back to authenticate and verify its plaintext size and hash, then upload Sync Commits before conditionally advancing one Head object with the ETag they previously read. Mutable Head reads request origin revalidation and a no-store response. Strong response ETags are normalized to an HTTP entity tag before being reused in `If-Match`, while weak or malformed values stop synchronization; this prevents a cached Head or bridge-specific quote removal from creating permanent false contention. A concurrent update rejects a genuinely stale Head write, causing that Replica to read, reconcile, and retry instead of silently overwriting another Replica's changes.
