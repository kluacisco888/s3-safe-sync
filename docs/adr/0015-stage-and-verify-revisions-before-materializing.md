# Stage and verify Revisions before materializing

Authenticated downloads become live Vault files only after the plaintext size and hash match the Revision, a plugin-private temporary file is written and verified, and the current local content still matches the Sync Plan. The journal records the original content hash; replacement verifies that the file moved to backup still has that hash before promoting the temporary file. Promotion uses the DataAdapter's no-overwrite copy operation, so a target recreated in the final race window stops the transaction instead of being replaced. Recovery restores a verified backup, keeps a verified promoted file, or stops with the journal and both ambiguous copies preserved for review. A transport failure while reading a remote recovery candidate is reported without being treated as evidence of corruption or absence; only authenticated validation failures allow the verifier to try another retained copy. A retired backup is verified again and moved to local trash rather than permanently deleted, protecting late writes through an already-open file handle. Remote moves likewise use no-overwrite copy, verify source and target hashes, then retire the source through local trash. Plugin-originated recovery, replacement, move, and deletion operations share one per-Vault mutation lock. Mobile processes one file at a time. Network transfer and decryption still restart after process termination; only final local materialization is currently recoverable.

For a verified remote rename interrupted after copying, reconciliation may finish source retirement when base identity, unique path ownership and unchanged source/target/remote content agree. The existing target is never overwritten. A failed remote-recovery check or changed local content preserves both paths; this is not general hash-based deduplication.

Empty-directory cleanup is a separate, post-acceptance desktop step scoped to ancestors of retired files. It uses real directory listings, directory/ancestor identity checks, and Node's directory-only rmdir under the mutation lock and host filesystem queue, followed by host index reconciliation. Any contents, protected path, link, unsupported capability or I/O failure cause preservation. Mobile cleanup stays disabled: the inspected host wrapper forces recursive deletion. These checks reduce ordinary races; they are not an atomic defense against arbitrary external replacement of ancestor directories.
